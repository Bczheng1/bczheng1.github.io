，而是用 源码 的方式和逻辑，使用LoadBlockIndex函数来读取，方便我们了解源码。

LoadBlockIndex有两个，一个是全局的，一个是CTxDB下的成员函数。

在全局函数中会调用CTxDB里的LoadBlockIndex，主要是这个函数实现的功能。

先来看一下全局函数的完整代码：

1.全局LoadBlockIndex

全局函数开始创建了一个CTxDB txdb对象以cr的方式，这个就是如果没有blkindex.dat文件则创建，如果有则打开。

然后就调用txdb.LoadBlockIndex加载索引数据。

加载完后，判断是否为空，也就是没索引数据，那说明创世块都没有创建，就会手动构建创世块。

然后调用WriteToDisk写入创世区块数据到磁盘，AddToBlockIndex写入创世区块索引到数据库。

全局LoadBlockIndex完成的就是这几个功能。主要是对创世块的判断。

我们先来看这句：

  1.     // 第一次循环时，设置查找条件：查找所有以 "blockindex" 开头的 key
  2.         if (fFlags == DB_SET_RANGE)

运行

这里设置ssKey为uint256(0),这里并不是要读取哈希值0的那个key的值。

因为这里使用了游标，跟普通的读取方式不一样，它不是指定key的。

前面它设置了DB_SET_RANGE，代表范围读取，意思是读取>=哈希值为0的key，

那么就是读取所有的blockindex，而排除了其它数据。这样的效率会高一些。

所以指定了这样一个key，并不一定要0这个key存在，只要符合要求，它都会定位到那条 数据读取 。

这就是ReadAtCursor的用法，那么当定位到那个key后，必须是从最小的开始，设置游标定位后，就可以改变读取行为，设置为fFlags = DB_NEXT;循环读取下一条。

这个跟普通的读取不一样，指定键，如下面的函数：

pdb->get()

它不怕被哈希值污染吗？因为sskey读到的并不只有string数据。这里并不会，这里因为序列化的时候，是将pair拆分的，拆分成string和哈希值，然后再拼在一起 存储 。

这样的话，因为前面是string数据，所以它会带一个大小，然后指定后面读多少字节。

所以sskey>>strType，strType是个string类型，它就只会反序列化前面的string部分。

  2. {

  4.     // 用于后续将每笔交易的位置（CDiskTxPos）写入交易索引数据库
  5.     unsigned int nTxPos = pindex->nBlockPos 
  6.                         + ::GetSerializeSize(CBlock(), SER_DISK) - 1 
  7.                         + GetSizeOfCompactSize(vtx.size());
  8.  
  9.     // 这个参数在此函数内无用，为了兼容ConnectInputs而写(会访问此变量)
  10.     map<uint256, CTxIndex> mapUnused;
  11.  
  12.     // 累计本块所有交易的手续费总和，用于后面验证 coinbase 奖励是否合法
  13.     int64 nFees = 0;
  14.  
  15.     // 遍历块中的每一笔交易（包括 coinbase）
  16.     foreach(CTransaction& tx, vtx)

  24.         // 核心操作：连接交易输入（检查双花、验证签名、更新UTXO）

7.nTxPos

我们先来看它的第一句：

   unsigned int nTxPos = pindex->nBlockPos + ::GetSerializeSize(CBlock(), SER_DISK) - 1 + GetSizeOfCompactSize(vtx.size());
cpp
运行

计算这个区块的第一笔交易在文件中的偏移位置（相对于blkxxxx.dat文件，非单个区块).

它是怎么计算的呢？是区块偏移位置,也就是pindex->nBlockPos。加上区块头的大小，CBlock()。我们前面知道区块头固定是80字节，所以交易数据要越过区块头，然后接一下是一小段字节用来描述这个区块有多少笔交易，但是这个字节是动态的，如果比如说吧只有5笔交易，是不是只用1个字节就能描述这个值了？如果超过255以上，是不是有多个字节。

所以这里用了GetSizeOfCompactSize(vtx.size()); 这个函数来根据大小动态计算字节。

跨过了这个字节后，才是交易数据。也就是这个区块的第一交易的起始位置。

至于这里的-1，是因为有个误差，会多算1个字节，所以固定减1。应该是 ::GetSerializeSize(CBlock(), SER_DISK)会多算一个字节，这里不验证了，有需要的可以自行调用这个函数获取一下值就知道了。

好，得到了第一笔交易的偏移值后。

8.CDiskTxPos

就会遍历这个区块的所有的交易，第循环一次，获取这笔交易的大小，然后加上这个值，就是下一笔交易的偏移位置。然后位置相关存储在CDiskTxPos里面，而这个CDiskTxPos是被包含在CTxIndex里面的，相对于区块索引CBlockIndex(CDiskBlockIndex),这个CTxIndex就是跟交易索引相关的类。
