通过之前我们知道，每一笔tx，即CTransaction，都有一个对应txid，即哈希值。但是我们看到

一个区块里，CBlock 有多个CTransaction，即数组形式： vector<CTransaction> vtx;那么一个区块里就有会多个交易的哈希值，但我们实际看到的，区块只包含有一个哈希值，它是怎么代表那么多的交易呢？即通过默克树的方式，通过某种方法将所有的交易哈希值进行汇总再哈希一次，就会得一个唯一的哈希值。接下来要介绍的就是默克尔树的哈希规则。

BuildMerkleTree函数

当交易构建好后，需要挖矿打包时，此时就会在挖矿函数BitcoinMiner里，生成默克树根。然后再对块整体进行哈希找到目标值上链。

所以我们能在这个函数看到如下代码：

 tmp.block.hashMerkleRoot = pblock->hashMerkleRoot = pblock->BuildMerkleTree();

那么关键点来了，是用块的BuildMerkleTree函数来获得默克尔树根哈希值。

所以搞懂这个函数，我们就能明白默克尔树的哈希规则。

接下来我们来看一下这个函数的源码：

  1.     uint256 BuildMerkleTree() const
  2.     {
  3.         vMerkleTree.clear();
  4.         foreach(const CTransaction& tx, vtx)
  5.             vMerkleTree.push_back(tx.GetHash());
  6.         int j = 0;
  7.         for (int nSize = vtx.size(); nSize > 1; nSize = (nSize + 1) / 2)
  8.         {
  9.             for (int i = 0; i < nSize; i += 2)
  10.             {
  11.                 int i2 = min(i+1, nSize-1);
  12.                 vMerkleTree.push_back(Hash(BEGIN(vMerkleTree[j+i]),  END(vMerkleTree[j+i]),
  13.                                            BEGIN(vMerkleTree[j+i2]), END(vMerkleTree[j+i2])));
  14.             }
  15.             j += nSize;
  16.         }
  17.         return (vMerkleTree.empty() ? 0 : vMerkleTree.back());
  18.     }

运行

这个函数做了两件事，一个是求默克尔根哈希，返回值就是。第二件事，将这个计算过程中，所有得到的节点哈希值都存在vMerkleTree这个数组里，线性储存，这个vMerkleTree在CBlock有定义：

  mutable vector<uint256> vMerkleTree;   就是一个uint256的vector数组，哈希值数组。

过程就是，开始时先将CBlock里的vtx,即每一个tx哈希，添加到vMerkleTree数组里。

然后，从0开始，两个哈希拼成一个字符串，进行哈希得到一个哈希值，hash函数实现这个功能（两次哈希，安全性更高）。

默克尔树规则

比如，现在有8个tx,这样，vtx[0]和vtx[1]这两个哈希经过上面这样处理后，就变成了一个哈希值了。然后2和3合成一个。接着到最后7和8，这样8个哈希就变成4个了。然后重复上面操作，4个变成2个，2个最终变成1个，最后一个就是根哈希，由于这种变法，从下往上越变越少，就像一颗树一样。所以叫默克尔树。用直白的话讲，就是，给你8个哈希值，但是你现在觉得太多了，你需要一个哈希值来描述它们。你怎么办？简单，直接将8个哈希值一次拼在一起，然后进行哈希，就得了唯一值。

但默克尔树不采用这种方法，它是每次哈希两个，得到一半的哈希数量后，再重复一直到只剩下一个。

但是这里有问题，如果哈希数量是奇数怎么办？方法是最后一个跟自身相哈希。这里在代码有体现，就是这句：

int i2 = min(i+1, nSize-1);
cpp
运行

如果nSize是奇数7个，那么当i执行到第三次，也就是为6时，会发生什么，min的数据就是这样min(7,6).

i2会等于6。也就是说i2不会是i+1,而是i2会和i相等。

那么这句：

  1.      vMerkleTree.push_back(Hash(BEGIN(vMerkleTree[j+i]),  END(vMerkleTree[j+i]),
  2.                                 BEGIN(vMerkleTree[j+i2]), END(vMerkleTree[j+i2])));
cpp
运行

传进去的就是两个相同的哈希。

接下来说一下这个函数的整体大概逻辑。

nSize获得初始tx数量，即int nSize = vtx.size(),然后每一次for循环两两计算完成后，就减半，

体现在nSize由(nSize+1)/2，取整赋值。这个过程中每两两得到一个哈希又添加到vMerkleTree里。之后通过，j+=nSize,控制不要哈希到前面的值，确保是后面一轮新添加的值。

程序的过程就是这样。

hash函数

接下来我们来重点看一下hash这个函数，这个函数我们之前使用过，但是那次是两个参数，而这次传进去的是四个参数，很明显hash函数有重载。我们来看一下这个重载代码：

  1. template<typename T1, typename T2>
  2. inline uint256 Hash(const T1 p1begin, const T1 p1end,
  3.                     const T2 p2begin, const T2 p2end)
  4. {
  5.     uint256 hash1;
  6.     SHA256_CTX ctx;
  7.     SHA256_Init(&ctx);
  8.     SHA256_Update(&ctx, (unsigned char*)&p1begin[0], (p1end - p1begin) * sizeof(p1begin[0]));
  9.     SHA256_Update(&ctx, (unsigned char*)&p2begin[0], (p2end - p2begin) * sizeof(p2begin[0]));
  10.     SHA256_Final((unsigned char*)&hash1, &ctx);
  11.     uint256 hash2;
  12.     SHA256((unsigned char*)&hash1, sizeof(hash1), (unsigned char*)&hash2);
  13.     return hash2;
  14. }
cpp
运行

在这个hash函数中，我们看到了一个不认识的 类 型，SHA256_CTX,还有几个函数,SHA256_Init,SHA256_Update,SHA_Final。

这几个是 openssl 库里的类型和函数，跟SHA256一次哈希函数不同的是，这几个配合可以进行多次哈希，用于分批处理文件之类的哈希，当然两个哈希拼接处理更是可以。

先来说下怎么使用，SHA256_CTX,大概就是储存数据的结构体，里面有hash[8]之类的数据，8个用运行哈希运行的初始值，以及接收你要哈希数据的缓冲区之类的。

所以我们需要先定义这样一个变量ctx，用于接收哈希的数据。

然后需要调用函数SHA256_init用于初始化，就是给ctx里hash[8]初始值。

接着，接收数据就用SHA256_Update函数，可以看到，调用了两次SHA256_Update.就是将默克尔树两个哈希值的数据都存进了ctx。

然后调用SHA256_Final进行哈希。得到hash1值，接着调用SHA256一次哈希函数，对hash1再次进行哈希(这就是两次哈希).

我们可以看到SHA256_Final和SHA256的区别，其中SHA256哈希也是采用SHA256_init用来初始8个值的，但是我们在之前的调用并没有看到，这里的原因是SHA256是一次哈希的，所以它是在函数内部调用了，并不需要放到函数里去。而SHA256_Final在哈希之前还要SHA256_Update多段数据，这个值是会随着多段数据而变化的，所以没法在函数里调用Init ctx，那样hash[8]的值就是不是正确的值。
