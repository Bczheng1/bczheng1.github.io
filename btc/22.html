1.找到签名

要了解交易签名，我们需要知道这个签名是在哪里生成的，而验证部分我们之前已经接触到一些：

在ConnectInputs函数里，会调用这个函数进行验证：

  1.   // Verify signature
  2.   if (!VerifySignature(txPrev, *this, i))
  3.       return error("ConnectInputs() : %s VerifySignature failed", GetHash().ToString().substr(0,6).c_str());
cpp
运行

txPrev有花费者指向的那笔vout，*this就是你构建好的交易，i指明是第几个vin.有这几个关键的参数，就可以调用VerifySignature来验证了。说明这里的*this已经包含签名了，构建好了。

那么是上级创建了一笔tx，然后调用tx.ConnectInputs来验证的，是这么个逻辑，那么找到这笔交易创建的地方，就能找到签名。

但是前面说过，AcceptBlock那边的逻辑也调用了ConnectInputs，挖矿函数也调用了这个函数。我们应该去哪里找这个签名呢，判断是谁生成的呢？

答案是是沿着挖矿函数这个路径上去找，因为AcceptBlock接受的是已经生成了的tx，这个是别人的节点的块，发送给你，也需要验证。而这个签名也是别人的节点的挖矿时生成的。

最终也是指向挖矿函数，所以我们从这一路开始找签名生成。

3.mapTransactions

可以看到，里面的tx是从mapTransactions获取到的，这个就是内存交易池，所以我们得找到内存交易池创建地方。

但这里说一下从内存池抓取到一笔交易后，生成一个tx，然后调用tx下的ConnectInputs函数。

这个函数的需要一些参数，其中，第一个参数txdb数据库相关，以及第三个参数CDiskTxPos(1,1,1)，因为块没写入磁盘，所以指定特殊位置标志。

还有后面的一些参数我们都了解。

但是第二个参数mapTestPool，即map<uint256, CTxIndex>  类 型，为什么需要这个参数，验证是用来做什么，以及这个参数是怎么生成的。我们的印象不是很深刻，所以这里说明一下。

是因为验证时，需要指向的交易索引，查一下未花费的情况，签名验证是都需要用到。

但是，如果指向的那一笔交易索引在磁盘上没有呢，也就是它们正好在同一个区块。

所以针对这种情况，需要构建一个临时的交易索引数组，即mapTestPool。

即在碰盘上查不到，可以到mapTestPool里查找。

然后来看一下mapTestPool生成逻辑，这里排除coinbase交易，这个在别的地方构造，后续所说的第一笔交易，是在排除了coinbase的情况下。

由于是第一笔交易，那么此时mapTestPool.count肯定返回的是假，因为mapTestPool里面啥也没有。

然后会到数据库里找这笔引用的交易，但此时如果它引用的同一个区块的交易呢？

它在数据库里也找不到。那么此时fMKiner也为真，在挖矿。它就会执行feturn fMiner?，返回假，这笔交易被打回去了。

这种情况会发生吗？会发生的，问题出在，一个区块内第一笔交易引用第三笔交易，这种情况是不允许的，前一笔交易引用后一笔交易，首先不管同一个区块引用的也是同一个区块的交易，但它最终的来源肯定不是无中生有的，肯定更前前一个交易是来自数据库的。

那么这里对排序有着要要求，第一笔交易得是来自数据库之类的最终来源（如果由于意外后面的交易排到前面了就会退回去）。所以找到这笔交易，就会构建开始的mapTestPool，然后再循环添加被打回去的交易。此时被打回去的交易已经能在mapTestPool找到对应的引用了（假设在同一区块）

好，这笔交易通过验证后，又被加入mapTestPool了，这就是mapTestPool的构建逻辑。

而我们也能在之前区块记录中看见，引用，总是后一笔交易引用前一笔交易，就是这么来的。

在同一个区块中也得符合这个设定。

好，回到正题。我们回到生成的tx，tx.ConnectInputs，这里的tx是从mapTransactions提取出来的，在此之前签名已经生成 ，那么我们往上找mapTransactions是怎么构建的。

9.CreateTransaction

在SendMoney中会调用如下函数创建交易（根据收款账号和金额）,找uxto找合适的vin然后构建交易，并计算手续费，然后构造好合适的vout，如有找零。交易构造好，再进行签名：完整代码如下：

  1. bool CreateTransaction(CScript scriptPubKey, int64 nValue, CWalletTx& wtxNew, int64& nFeeRequiredRet)
  2. {
  3.     // nFeeRequiredRet 用于返回给调用者：本次交易最终实际需要的手续费
  4.     nFeeRequiredRet = 0;
  5.  
  6.     // 锁定主临界区，防止其他线程同时修改区块链状态
  7.     CRITICAL_BLOCK(cs_main)
  8.     {
  9.         // 必须在锁定 mapWallet 之前打开 txdb（数据库读取顺序要求）
  10.         CTxDB txdb("r");                    // 以只读模式打开交易数据库
  11.  
  12.         // 锁定钱包数据库，防止其他操作同时修改钱包
  13.         CRITICAL_BLOCK(cs_mapWallet)
  14.         {
  15.             // nFee 是当前循环中使用的“预估手续费”，初始值为全局配置的手续费
  16.             int64 nFee = nTransactionFee;
  17.  
  18.             // loop = 无限循环（相当于 for(;;)），用于手续费不够时重新尝试
  19.             loop
  20.             {
  21.                 // 每次循环开始时，清空上一次构建的输入和输出
  22.                 wtxNew.vin.clear();
  23.                 wtxNew.vout.clear();
  24.  
  25.                 // 发送金额不能为负数
  26.                 if (nValue < 0)
  27.                     return false;
  28.  
  29.                 // nValueOut 是真正要支付给对方的金额（不包含手续费）
  30.                 int64 nValueOut = nValue;
  31.  
  32.                 // 把目标金额临时增加预估手续费，用于挑选足够的输入
  33.                 nValue += nFee;
  34.  
  35.                 // ====================== 挑选 UTXO（输入） ======================
  36.                 // setCoins 用于存放本次选中的钱包交易（即 UTXO）
  37.                 set<CWalletTx*> setCoins;
  38.  
  39.                 // SelectCoins：根据 nValue（金额 + 预估手续费）从钱包中挑选足够金额的 UTXO
  40.                 if (!SelectCoins(nValue, setCoins))
  41.                     return false;               // 余额不足，直接返回失败
  42.  
  43.                 // 计算所有选中 UTXO 的总输入金额（nValueIn）
  44.                 int64 nValueIn = 0;
  45.                 foreach(CWalletTx* pcoin, setCoins)
  46.                     nValueIn += pcoin->GetCredit();   // GetCredit() 返回该交易中属于自己的可用金额
  47.  
  48.                 // ====================== 构建输出 vout ======================
  49.  
  50.                 // vout[0]：支付给收款人（张三）
  51.                 wtxNew.vout.push_back(CTxOut(nValueOut, scriptPubKey));
  52.  
  53.                 // 如果有找零（输入金额 > 输出金额 + 手续费）
  54.                 if (nValueIn > nValue)
  55.                 {
  56.                     // 使用选中 UTXO 中第一个输出的公钥作为找零地址（保持使用同一个地址风格）
  57.                     vector<unsigned char> vchPubKey;
  58.                     CTransaction& txFirst = *(*setCoins.begin());   // 取第一个选中的交易
  59.  
  60.                     foreach(const CTxOut& txout, txFirst.vout)
  61.                         if (txout.IsMine())                         // 找到属于自己的输出
  62.                             if (ExtractPubKey(txout.scriptPubKey, true, vchPubKey))
  63.                                 break;
  64.  
  65.                     if (vchPubKey.empty())
  66.                         return false;
  67.  
  68.                     // 构造找零的 scriptPubKey（公钥 + OP_CHECKSIG）
  69.                     CScript scriptPubKey;
  70.                     scriptPubKey << vchPubKey << OP_CHECKSIG;
  71.  
  72.                     // vout[1]：找零输出，金额 = 总输入 - 要支付的金额 - 手续费
  73.                     wtxNew.vout.push_back(CTxOut(nValueIn - nValue, scriptPubKey));
  74.                 }
  75.  
  76.                 // ====================== 构建输入 vin ======================
  77.                 // 把选中的 UTXO 全部加入 vin（输入）
  78.                 foreach(CWalletTx* pcoin, setCoins)
  79.                     for (int nOut = 0; nOut < pcoin->vout.size(); nOut++)
  80.                         if (pcoin->vout[nOut].IsMine())             // 只添加属于自己的输出
  81.                             wtxNew.vin.push_back(CTxIn(pcoin->GetHash(), nOut));
  82.  
  83.                 // ====================== 对所有输入进行签名 ======================
  84.                 int nIn = 0;   // 输入序号
  85.                 foreach(CWalletTx* pcoin, setCoins)
  86.                     for (int nOut = 0; nOut < pcoin->vout.size(); nOut++)
  87.                         if (pcoin->vout[nOut].IsMine())
  88.                             SignSignature(*pcoin, wtxNew, nIn++);   // 对第 nIn 个输入进行签名
  89.  
  90.                 // ====================== 检查手续费是否足够 ======================
  91.                 // GetMinFee(true) 根据当前交易的实际大小重新计算需要的手续费
  92.                 if (nFee < wtxNew.GetMinFee(true))
  93.                 {
  94.                     // 手续费不够 → 更新手续费为实际需要的金额，并重新循环
  95.                     nFee = nFeeRequiredRet = wtxNew.GetMinFee(true);
  96.                     continue;                     // 跳回 loop 重新挑选 UTXO、重建交易
  97.                 }
  98.  
  99.                 // ====================== 完成交易构建 ======================
  100.                 // 把这笔交易依赖的前置交易信息复制进来（用于以后验证）
  101.                 wtxNew.AddSupportingTransactions(txdb);
  102.  
  103.                 // 标记这笔交易的时间使用“接收时间”（自己创建的交易也这样标记）
  104.                 wtxNew.fTimeReceivedIsTxTime = true;
  105.  
  106.                 break;        // 手续费足够，退出 loop，交易构建成功
  107.             }   // end loop
  108.         }       // end cs_mapWallet
  109.     }           // end cs_main
  110.  
  111.     return true;    // 返回成功，此时 wtxNew 中已经是完整签名好的交易
  112. }
