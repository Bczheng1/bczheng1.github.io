 3.哈希运算

什么是哈希运算？

 哈希运算可以将任意大小的数据生成一个特定大小的数字或字符串，这个数字或字符串就是哈希值，比如生成20字节哈希值就叫SHA-1运算，32字节的是SHA-256，64字节的是SHA-512。

而MD5是产生128位二进制，即16个字节的哈希值。当然哈希值的字节可以不是固定的，具体看算法。

这个不是重点，只要在安全的范围内，都可以。

什么叫安全的范围内呢？

即这个哈希值的特性，只要你运算的数据，哪怕有一个bit位不同，它的哈希值都是会变的。会有巨大的不同。

下面分别对这三个要求详细说明

3.1数据填充

第一:需要在数据未尾添加一个二进制1，而因为不管是系统还是sha运算都是按字节处理的。

所以也可以说在后面添加一个字节，这个字节的16进制值是0x80。

比如说hello吧，占5个字节，如果你在这个数据结尾加上一个二进制1，

那它只能是第六个字节开头，并且这个字节是这样的形式：

1000 0000 即16进制的0x80

第二：添加一个二进制1后，如果小于56字节(即64-8），则将后续所有的位填充0，直到56个字节。这里有两点要说明，其实这里按位数算更严谨一些。只是为了方便阅读理解。

就这样用字节说了，结果是没问题的。包括小于56字节，即小于448位，全部二进制位补0。

为什么，你在1000 0000，也就是开头第1个二进制后面添加0，它还是1000 0000。

所以补个值为0x80的字节就行了。

然后是，还剩8个字节，这8个字节是预留的，是用来描述原数据的大小的，占多少二进制位。

比如hello是5个字节，5x8=40,即0x28,那么这个8字节填充的就是(16进制表达)：

00 00 00 00 00 00 00 40

这样处理后刚好达到了64个字节。

上面是不足64字节的填充方案，如果超过64字节呢？

比如84个字节的数据，还是先在未尾补个二进制1，然后不足64的倍数减8，即128-8，补0。

剩下8个字节用来描述原始数据大小。

注意这里的不超过64个字节，并不是说64字节就不要补了。

补1和预留8字节这两个是必须的。我这个64字节是描述的是补充后的字节数。

而补0有时候是不需要的，比如刚好55个字节，加上0x80 56个字节，然后预留8个字节

刚好64字节，这种情况就不用补0了。

好了，我们不需要自己编写这个代码，只需要有个大概的了解就行了。

因为在源码中已经实现了，在main.cpp中的FormatHashBlocks函数内

  1. int FormatHashBlocks(void* pbuffer, unsigned int len)
  2. {
  3.     unsigned char* pdata = (unsigned char*)pbuffer;
  4.     unsigned int blocks = 1 + ((len + 8) / 64);
  5.     unsigned char* pend = pdata + 64 * blocks;
  6.     memset(pdata + len, 0, 64 * blocks - len);
  7.     pdata[len] = 0x80;
  8.     unsigned int bits = len * 8;
  9.     pend[-1] = (bits >> 0) & 0xff;
  10.     pend[-2] = (bits >> 8) & 0xff;
  11.     pend[-3] = (bits >> 16) & 0xff;
  12.     pend[-4] = (bits >> 24) & 0xff;
  13.     return blocks;
  14. }

3.3大小端序

最后需要处理的数据，要按照大端序存储，因为sha256规定是处理的数据为大端序，输出的哈希值也是大端序。

什么是大小端序呢？就是数据的存储方式。

比如  short a = 411; 两个字节的类型，411的二进制是：

00000001 10011011

那么在x86下，也就我们现在用的windows,低字节存储在低地址下。

比如a的首地址是0x1e8   那么这个就存储10011011  然后是 0x1e9 存储00000001

这就是小端序存储。

那么大端序就是反过来了，注意，这是按字节来反转的，比如int a有四个字节，那就要反转四个。

而不是按二进制位。

所以我们还要将数据反转一下，一跟上面一样，也不用我们写代码了，源码中有，在sha.h中,

 ByteReverse函数，如下代码：

  1. inline byte ByteReverse(byte value)
  2. {
  3.     return value;
  4. }
  5.  
  6. inline word16 ByteReverse(word16 value)
  7. {
  8. #ifdef CRYPTOPP_BYTESWAP_AVAILABLE
  9.     return bswap_16(value);
  10. #elif defined(_MSC_VER) && _MSC_VER >= 1300
  11.     return _byteswap_ushort(value);
  12. #else
  13.     return rotlFixed(value, 8U);
  14. #endif
  15. }
  16.  
  17. inline word32 ByteReverse(word32 value)
  18. {
  19. #if defined(__GNUC__)
  20.     __asm__ ("bswap %0" : "=r" (value) : "0" (value));
  21.     return value;
  22. #elif defined(CRYPTOPP_BYTESWAP_AVAILABLE)
  23.     return bswap_32(value);
  24. #elif defined(__MWERKS__) && TARGET_CPU_PPC
  25.     return (word32)__lwbrx(&value,0);
  26. #elif _MSC_VER >= 1400 || (_MSC_VER >= 1300 && !defined(_DLL))
  27.     return _byteswap_ulong(value);
  28. #elif CRYPTOPP_FAST_ROTATE(32)
  29.     // 5 instructions with rotate instruction, 9 without
  30.     return (rotrFixed(value, 8U) & 0xff00ff00) | (rotlFixed(value, 8U) & 0x00ff00ff);
  31. #else
  32.     // 6 instructions with rotate instruction, 8 without
  33.     value = ((value & 0xFF00FF00) >> 8) | ((value & 0x00FF00FF) << 8);
  34.     return rotlFixed(value, 16U);
  35. #endif
  36. }

 这里 ByteReverse有三个重载，分别反转不同大小的类型数据。

第一个byte，直接是一个字节，不需要反转。直接返回。然后是word16 2个字节。

最后是word32 4个字节，是我们需要用到的。一次处理四个字节。

注意这个函数有许多宏定义判断，是因为这里的源码是从cryptopp库里提取出来的。

cryptopp库为了兼容性，保证在不同的平台来编译成功，才这样写的。

ok,接下来我们来写个完整的例子，上面的初始值和小端序转大端序，中本聪已经帮我们写好了，就是main.cpp中的BlockSha256函数：

  1. void BlockSHA256(const void* pin, unsigned int nBlocks, void* pout)
  2. {
  3.     unsigned int* pinput = (unsigned int*)pin;
  4.     unsigned int* pstate = (unsigned int*)pout;
  5.  
  6.     CryptoPP::SHA256::InitState(pstate);
  7.  
  8.     if (*(char*)&detectlittleendian != 0)
  9.     {
  10.         for (int n = 0; n < nBlocks; n++)
  11.         {
  12.             unsigned int pbuf[16];
  13.             for (int i = 0; i < 16; i++)
  14.                 pbuf[i] = ByteReverse(pinput[n * 16 + i]);
  15.             CryptoPP::SHA256::Transform(pstate, pbuf);
  16.         }
  17.         for (int i = 0; i < 8; i++)
  18.             pstate[i] = ByteReverse(pstate[i]);
  19.     }
  20.     else
  21.     {
  22.         for (int n = 0; n < nBlocks; n++)
  23.             CryptoPP::SHA256::Transform(pstate, pinput + n * 16);
  24.     }
  25. }

4.区块链

有了哈希运算后，接下来我们通过块的哈希值把区块链一个一个的连起来。

比如我们将某个区块的数据进行哈希运算，生成了独一无二的哈希值。

接着下一个块，包含前一个块的哈希值，然后再哈希运算。依此类推，把它们一个个链接起来。

这样生成的数据具有不可篡改性，如果你改变了其中一个区块数据，其后面所有的区块哈希值都不匹配了。 因为这种构造特性，就被称为区块链(关于更详细的说明和使用，将在后续章节介绍)。

所以回到开始，说一下这个安全性。

这个哈希值的范围就必须足够大，如果范围不够大，比如10字节，很容易就生成一样的哈希值，这样是不安全的。而sha256 32字节就足够安全，这个数字范围是2的256次方,有个比喻说，这比整个宇宙原子的数量还多。
