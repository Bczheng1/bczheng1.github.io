2.ReadFromDisk重载

类 里的ReadFromDisk调用了另一个重载ReadFromDisk函数实现的，该函数代码如下：

  1. // 从磁盘的 blk*.dat 文件中读取一个区块数据
  2. bool ReadFromDisk(unsigned int nFile, unsigned int nBlockPos, bool fReadTransactions)
  3. {
  4.     // 先把当前区块对象清空，恢复到初始状态
  5.     SetNull();
  6.  
  7.     // 打开对应的历史区块文件（blk00001.dat、blk00002.dat 等）
  8.     // nFile 表示第几个 blk 文件，nBlockPos 表示该区块在文件中的偏移位置（字节）
  9.     // "rb" 表示以二进制只读方式打开
  10.     CAutoFile filein = OpenBlockFile(nFile, nBlockPos, "rb");
  11.     
  12.     // 如果文件打开失败，返回错误
  13.     if (!filein)
  14.         return error("CBlock::ReadFromDisk() : OpenBlockFile failed");
  15.  
  16.     // 如果调用者明确表示不需要读取交易数据（只想读区块头），则设置序列化标志
  17.     // SER_BLOCKHEADERONLY 表示只反序列化区块头（80字节），跳过后面的交易部分
  18.     // 这可以大大加快只验证区块头的场景（如初始同步时的头部同步）
  19.     if (!fReadTransactions)
  20.         filein.nType |= SER_BLOCKHEADERONLY;
  21.  
  22.     // 从文件中读取区块数据到当前对象 (*this)
  23.     // 这里会根据上面的标志决定是读取完整区块还是只读取区块头
  24.     filein >> *this;
  25.  
  26.     // ==================== 区块头合法性检查 ====================
  27.  
  28.     // 检查 nBits（难度目标值）是否合法
  29.     // 把 nBits 转换成大整数后，与当前网络的 ProofOfWork 上限进行比较
  30.     // 如果 nBits 比允许的最大难度目标还大（即难度太低），则认为非法
  31.     if (CBigNum().SetCompact(nBits) > bnProofOfWorkLimit)
  32.         return error("CBlock::ReadFromDisk() : nBits errors in block header");
  33.  
  34.     // 检查区块哈希是否满足当前难度要求（即工作量证明 PoW 是否达标）
  35.     // GetHash() 是整个区块头的哈希
  36.     // 如果区块哈希 > 当前难度目标值，说明没有达到挖矿要求的难度，属于无效区块
  37.     if (GetHash() > CBigNum().SetCompact(nBits).getuint256())
  38.         return error("CBlock::ReadFromDisk() : GetHash() errors in block header");
  39.  
  40.     // 所有检查都通过，读取成功
  41.     return true;
  42. }

4.bnProofOfWorkLimit

然后是这个变量定义：在main.h定义一下

static const CBigNum bnProofOfWorkLimit(~uint256(0) >> 32);
cpp
运行

这是一个固定的值，难度不能低于这个值，用代码表示，对应着这句：

   if (CBigNum().SetCompact(nBits) > bnProofOfWorkLimit)
cpp
运行

你设定的难度，通过nBits，就是规定前几个0的。不能大于bnProofWorkLimit。

假设这个bnProofOfWorkLimit,规定前面必须是两个0以上，比如001就是它的值。

如果你设定只有一个0，这样是不是难度比它小呢？那么011>001,表达式成立。

难度太低，所以不合法。这个bnProofOfworkLimit值具体是多少呢？

uint256(0),256位全是0，然后~取反，变成全是1,然后右移32位，空出的位补0.所以这个值前32位全是0，8位一个字节，那么就是4个字节，16进制表达，就是0x00000000ffff.....就是这么一个值。

这个规定了挖矿的最低难度。

然后再看这句：

  1. if (GetHash() > CBigNum().SetCompact(nBits).getuint256())
  2.         return error("CBlock::ReadFromDisk() : GetHash() errors in block header");

运行

根据这个块的难度（就是其下的nBits)生成具体的值,然后调用GetHash获得哈希，对比这个值是否合法，就是是否符合这个难度。

注意，这里我们之前给的nNonce，是随便给的，不是通过挖矿得来的，所以这一句我们是非法的。现在要么暂时去掉这句，要么加入挖矿函数，通过不断的调整nNonce这个值，找到符合目标的哈希值。

8.AddToBlockIndex
  1. bool CBlock::AddToBlockIndex(unsigned int nFile, unsigned int nBlockPos)
  2. {
  3.     // Step 1: 检查是否已经存在相同的区块（防止重复添加）
  4.     uint256 hash = GetHash();                                      // 计算当前区块的哈希值
  5.     if (mapBlockIndex.count(hash))                                 // 如果 mapBlockIndex 中已经存在该区块哈希
  6.         return error("AddToBlockIndex() : %s already exists", hash.ToString().substr(0,14).c_str());
  7.  
  8.     // Step 2: 创建新的区块索引对象
  9.     CBlockIndex* pindexNew = new CBlockIndex(nFile, nBlockPos, *this);   // 用当前区块的信息构造 CBlockIndex 对象
  10.     if (!pindexNew)                                                    // 如果内存分配失败
  11.         return error("AddToBlockIndex() : new CBlockIndex failed");
  12.  
  13.     // Step 3: 将新区块索引插入到全局 mapBlockIndex 中
  14.     map<uint256, CBlockIndex*>::iterator mi = mapBlockIndex.insert(make_pair(hash, pindexNew)).first;
  15.     pindexNew->phashBlock = &((*mi).first);                        // 让 pindexNew 指向 map 中存储的 hash（避免拷贝）
  16.  
  17.     // Step 4: 查找前一个区块，建立链式关系
  18.     map<uint256, CBlockIndex*>::iterator miPrev = mapBlockIndex.find(hashPrevBlock);
  19.     if (miPrev != mapBlockIndex.end())                             // 如果能找到上一个区块
  20.     {
  21.         pindexNew->pprev = (*miPrev).second;                       // 设置前向指针
  22.         pindexNew->nHeight = pindexNew->pprev->nHeight + 1;        // 计算当前区块的高度（比上一个高1）
  23.     }
  24.  
  25.     // Step 5: 开始数据库事务，准备写入区块索引
  26.     CTxDB txdb;                                                    // 打开区块索引数据库
  27.     txdb.TxnBegin();                                               // 开始事务
  28.  
  29.     // 将新区块索引写入数据库（使用磁盘格式 CDiskBlockIndex）
  30.     txdb.WriteBlockIndex(CDiskBlockIndex(pindexNew));
  31.  
  32.     // Step 6: 判断是否需要更新“最优链”（New Best）
  33.     if (pindexNew->nHeight > nBestHeight)                          // 如果当前区块高度高于当前最优链高度
  34.     {
  35.         // 情况1：这是创世区块
  36.         if (pindexGenesisBlock == NULL && hash == hashGenesisBlock)
  37.         {
  38.             pindexGenesisBlock = pindexNew;                        // 记录创世区块索引
  39.             txdb.WriteHashBestChain(hash);                         // 记录最优链的最后一个哈希
  40.         }
  41.         // 情况2：直接接在当前最优链后面（最常见情况）
  42.         else if (hashPrevBlock == hashBestChain)
  43.         {
  44.             // 尝试把新区块连接到主链
  45.             if (!ConnectBlock(txdb, pindexNew) || !txdb.WriteHashBestChain(hash))
  46.             {
  47.                 txdb.TxnAbort();                                   // 连接失败，回滚事务
  48.                 pindexNew->EraseBlockFromDisk();                   // 删除磁盘上的区块数据
  49.                 mapBlockIndex.erase(pindexNew->GetBlockHash());    // 从内存 map 中删除
  50.                 delete pindexNew;                                  // 释放内存
  51.                 return error("AddToBlockIndex() : ConnectBlock failed");
  52.             }
  53.  
  54.             txdb.TxnCommit();                                      // 提交事务
  55.             pindexNew->pprev->pnext = pindexNew;                   // 设置后向指针，形成双向链表
  56.  
  57.             // 从内存池中删除已经打包进区块的交易
  58.             foreach(CTransaction& tx, vtx)
  59.                 tx.RemoveFromMemoryPool();
  60.         }
  61.         // 情况3：出现分叉，需要进行链重组（Reorganize）
  62.         else
  63.         {
  64.             if (!Reorganize(txdb, pindexNew))
  65.             {
  66.                 txdb.TxnAbort();
  67.                 return error("AddToBlockIndex() : Reorganize failed");
  68.             }
  69.         }
  70.  
  71.         // 更新全局最优链指针
  72.         hashBestChain = hash;
  73.         pindexBest = pindexNew;
  74.         nBestHeight = pindexBest->nHeight;
  75.         nTransactionsUpdated++;                                    // 通知交易已更新
  76.  
  77.         printf("AddToBlockIndex: new best=%s  height=%d\n", 
  78.                hashBestChain.ToString().substr(0,14).c_str(), nBestHeight);
  79.     }
  80.  
  81.     // Step 7: 如果上面没有进入 if 分支（高度没有更新），这里提交事务
  82.     txdb.TxnCommit();
  83.     txdb.Close();                                                  // 关闭数据库
  84.  
  85.     // Step 8: 如果这个区块成为了新的最优区块，则广播钱包中尚未确认的交易
  86.     if (pindexNew == pindexBest)
  87.         RelayWalletTransactions();
  88.  
  89.     MainFrameRepaint();                                            // 刷新界面（老版本有 GUI 时使用）
  90.     
  91.     return true;                                                   // 添加成功
  92. }

注意这里啊insert()

返回一个 std::pair<iterator, bool>：

  • .first → 一个迭代器（map<uint256, CBlockIndex*>::iterator），指向被插入的元素（或已经存在的元素）。

9.1TxnBegin

首先构造txdb对象，然后调用TxnBegin()函数使用事务，确保一次性写入完整，这个函数，是需要TxnCommit()，TxnAbort()来配合使用的，当所有的数据写入正常（写入事务中），则会调用TxnCommit()来完成确认（一次性写入）。确保所有的数据一致写入性。如果其中有一条写入错误，则会调用TxnAbort()来回滚数据。确保所有的数据不会写入，确保不会有些数据写入有些没写入，造成混乱干扰。

当然TxnCommit本身也会失败，这个就不用担心了，失败就是没写入。这次本身是一个整体的数据了。那当然不会有分散的数据写上去。

稍后我们将会在代码看到，在什么情况下调用了TxnCommit和TxnAbort。

9.3CDiskBlockIndex

但是这里有个问题，不是直接写的CBlockIndex对象，而是还要将它转换成CDiskBlockIndex,这是为什么呢，我们来看一下这个类的代码：

  1. class CDiskBlockIndex : public CBlockIndex
  2. {
  3. public:
  4.     uint256 hashPrev;
  5.     uint256 hashNext;
  6.  
  7.     CDiskBlockIndex()
  8.     {
  9.         hashPrev = 0;
  10.         hashNext = 0;
  11.     }
  12.  
  13.     explicit CDiskBlockIndex(CBlockIndex* pindex) : CBlockIndex(*pindex)
  14.     {
  15.         hashPrev = (pprev ? pprev->GetBlockHash() : 0);
  16.         hashNext = (pnext ? pnext->GetBlockHash() : 0);
  17.     }
  18.  
  19.     IMPLEMENT_SERIALIZE
  20.     (
  21.         if (!(nType & SER_GETHASH))
  22.             READWRITE(nVersion);
  23.  
  24.         READWRITE(hashNext);
  25.         READWRITE(nFile);
  26.         READWRITE(nBlockPos);
  27.         READWRITE(nHeight);
  28.  
  29.         // block header
  30.         READWRITE(this->nVersion);
  31.         READWRITE(hashPrev);
  32.         READWRITE(hashMerkleRoot);
  33.         READWRITE(nTime);
  34.         READWRITE(nBits);
  35.         READWRITE(nNonce);
  36.     )
  37.  
  38.     uint256 GetBlockHash() const
  39.     {
  40.         CBlock block;
  41.         block.nVersion        = nVersion;
  42.         block.hashPrevBlock   = hashPrev;
  43.         block.hashMerkleRoot  = hashMerkleRoot;
  44.         block.nTime           = nTime;
  45.         block.nBits           = nBits;
  46.         block.nNonce          = nNonce;
  47.         return block.GetHash();
  48.     }
  49.  
  50.  
  51.     string ToString() const
  52.     {
  53.         string str = "CDiskBlockIndex(";
  54.         str += CBlockIndex::ToString();
  55.         str += strprintf("\n                hashBlock=%s, hashPrev=%s, hashNext=%s)",
  56.             GetBlockHash().ToString().c_str(),
  57.             hashPrev.ToString().substr(0,14).c_str(),
  58.             hashNext.ToString().substr(0,14).c_str());
  59.         return str;
  60.     }
  61.  
  62.     void print() const
  63.     {
  64.         printf("%s\n", ToString().c_str());
  65.     }
  66. };
cpp
运行

这是因为CBlockIndex的成员，比如哈希值，上一个区块的哈希，都是以指针的形式存储，那么这种数据是动态的，当程序重启后，这种数据都是无效的，会不一样的。

所以得将存储他们实际的值，而不是指针地址。CDiskBlockIndex就是完成这样一种转换。
